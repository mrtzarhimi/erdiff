## Other audit observations

- Phase-1 train augmentation repeats each trial `augment_multiplier` times and adds trialwise Gaussian noise proportional to that trial’s standard deviation (`dataloader.py:9-54`); validation receives no noise. The official generic `models/dataloader.py` exposes the same `AddGaussianNoise(factor=.08)` transform, but exact use in the official NHP pipeline was not verified.
- `torch.manual_seed(seed)` is called inside `get_nhp_dataloaders` (`dataloader.py:167`), resetting global Torch RNG for each loader construction. In Phase 2, source loader construction, target loader construction, then source-bank extraction and training all share this reset pattern; sampler/noise/augmentation random streams therefore depend on loader call order. This is a reproducibility risk, not yet measured.
- The active input data does not show an explicit neural normalization step; velocity normalization is fit on the training split only (`dataloader.py:178-183`). Because the active implementation smooths `spike_counts` and calls them firing-rate profiles, confirm whether those values are already binned counts/rates and what their time resolution is before changing preprocessing.
- `cross_day.py` has `subprocess.run` calls that would launch project programs if invoked. They were inspected but not invoked.

## Approved fix resolutions (2026-11-05)

- **A1 — target-label checkpoint selection: implemented.** `train_phase2.py` no longer evaluates target velocity during alignment or selects a state by target R². It saves the final read-in after a fixed, configured epoch count. Target batches omit behavior fields.
- **A2 — validation/test reuse: implemented.** The loader now produces deterministic, disjoint train/validation/test trial groups. Evaluation reads only the test loader; Phase 2 constructs neither validation nor test loaders.
- **A3 — behavior-dependent window selection and split overlap: implemented with a documented protocol change.** Windows are fixed from go-cue timestamps rather than target speed peaks. Overlapping raw time intervals are grouped before splitting so adjacent/overlapping samples cannot land in different partitions. Spike smoothing is performed within each extracted trial window, avoiding cross-trial smoothing contamination. The fixed neural lag and success-trial filter remain and need domain review.
- **Velocity scaling: implemented.** Phase 1 checkpoints store mean/std fit only on source training trials. Phase 2 requires these statistics and copies them into its checkpoint; missing statistics produce a clear error. Target evaluation applies that source transform and converts predictions and targets back to physical units before metrics/plots.
- **Determinism: implemented.** Split shuffling uses a local seeded generator and does not reset global Torch RNG. The cross-day orchestrator forwards its seed to each child command.
- **Neuron-count-specific loading: corrected.** `evaluate.py` now excludes both the source encoder read-in and source neural decoder read-out when loading source weights for a target session with a different neuron count, while retaining the source behavior decoder.
- **Baseline/result disclosure: clarified.** The pre-alignment state is now named a warm-start baseline because it can use target training spikes for the unequal-neuron initialization. Metrics include the split seed, held-out test-trial count, and alignment epoch count; cross-day CSV rows retain those fields.
- **Regression checks: added, not run.** `tests/test_evaluation_protocol.py` covers deterministic/disjoint splits, keeping overlapping windows in one partition, cue-derived bounds, and velocity inverse scaling. TDD red/green execution was not possible under the no-execution constraint.

These edits address evaluation leakage and scale bias, but they do not establish paper-level reproduction or prove runtime correctness. The trial window and within-trial smoothing changes are protocol decisions that should be compared against the official data pipeline when source data/code execution is authorized. The 4-bin neural lag and filtering to successful trials remain potential preprocessing choices to validate; success-only filtering conditions the evaluated population and must be reported as such. Cross-day orchestration still runs one seed at a time, so means/uncertainty across seeds are not produced automatically. The split code fails clearly if overlap grouping leaves fewer than three independent interval groups; whether the actual sessions satisfy this is unknown because no session data was read.
